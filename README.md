# 数学建模 Skill —— 一步一步怎么用

这套 Skill 帮你把一道数学建模题走完：**读懂题 → 定模型 → 写代码求解 → 写论文**。
你不用懂里面的细节，只要知道调用它之后会发生什么、每个环节要什么结果。下面就是完整流程。

---

## 第 0 步：怎么开始调用

直接把需求说给 Claude 就行，例如：

- 「用数学建模 Skill 完成这道题，生成 Word 论文」
- 「只帮我把这道题分析一下，选个模型」
- 「根据现有代码和结果，写完整论文.docx」
- 「把这版论文复查一遍，挑错」

你只说了哪部分，它就只走哪部分，**不会强行把三个阶段全跑完**。

---

## 第 1 步（必做）：先读懂题，建立「全局故事」

不管你要做哪一步，Claude 都会先老老实实把题目完整读一遍，而且：

- 连续读完整个题和各小问的关系，**不边读边填表、不急着挑模型**；
- 反复回读，直到能用大白话把题目讲清楚；
- 用三句话自检：
  1. 这道题真正要「保护 / 评价 / 预测 / 优化」的对象是什么？
  2. 什么情况算整体成功？什么情况算整体失败？
  3. 每一问是在推进总目标，还是只要一个局部结果？

**要点**：这一步最慢也最重要，题真读懂了后面才不会跑偏。题目有歧义时，Claude 会先停下来跟你说清楚，不会闷头猜。

---

## 第 2 步：确认你要做到哪一步，选路线

| 你想做 | 它就走 |
| --- | --- |
| 只想聊思路、读题、选模型 | 只做建模分析，口头回答，不产文件 |
| 写代码、求解、出图 | 先确认模型 → 进入编程 |
| 写论文 / 改论文 | 核对模型和真实结果 → 进入论文 |
| **完整完成整道题** | 建模 → 编程 → 论文，全走，允许中途回退修正 |
| 复查、挑错、交前终审 | 只查有风险的地方，不重跑全流程 |

---

## 第 3 步：完整流程的三段

### 阶段① 建模分析（建模手）

**干什么**：把题拆成子问题，选模型和算法，想好怎么验证。
**产出**：`题目分析报告.md`、`术语表格.md`。

**要点**：

- 先分清每问是「达标型」（算对就行）还是「竞赛型」（要拼最优，需要挑战策略）；
- 有数据先查字段、缺失、异常、量纲、时间空间范围，不瞎猜；
- 只有术语、机理、参数不确定时才查文献，**查完才冻结模型**；
- 确认题意没有歧义后（题意冻结），才进入下一步。

**门禁 M1（建模终检）**：只查真实风险——题目有没有被带偏、结论口径对不对。核心语义错了当场返工，不为小格式问题纠缠。

---

### 阶段② 代码求解（编程手）

**干什么**：写 Python / MATLAB 代码，真正把结果算出来，出表格和图。
**产出**：求解代码、`results/` 结果表格、`figures/` 图、`创新证据清单.json`、`复现清单.json`（只有「竞赛型」题目才有 `竞争性搜索账本.json`）。

**要点**：

- 先选语言 → 按需要查依赖（不一次性装所有包）→ 估计算量，算不动先想加速；
- **先跑通「最小可运行结果」，再全量计算和正式出图**，不一开始就闷头跑大的；
- 每张图先想清楚「给谁看、证明什么、数据从哪来」，不为了凑图而画图；
- 每张正式图导出可编辑 SVG + 至少 300 DPI PNG，并自动做灰度质检、人工复查；
- 每个创新点要有证据，写进创新证据清单；竞赛型要记「竞争性搜索账本」，说清楚怎么挑战最优、怎么判断能停。

**门禁 P1 / P2**：

- `P1`（最小可运行）：先过这一关，防止写一大坨最后全错；
- `P2`（编程终检）：全部算完、图出完、审计通过，才允许进论文阶段。

---

### 阶段③ 论文撰写（论文手）

**干什么**：把真实结果写成能提交的论文。**默认只生成 Word**（`.docx`），要 LaTeX/PDF 必须明确说。
**产出**：`完整论文.docx`。

**要点**：

- **先查输入齐不齐**：题目、分析报告、可运行代码、真实结果、证据清单，少一样就退回编程阶段补齐，**绝不凭空写**；
- 先建「证据大纲」：每一问的结论用哪张图 / 哪个表 / 哪个公式 / 哪篇文献来撑；
- 证据大纲通过后才写长篇正文，写的过程持续核对「说了什么 ↔ 有没有证据」；
- 格式服从目标竞赛**当届官方模板**（默认检索 2026 当届，不查其他届和评阅要点）；
- 没有官方值、没证明最优的结果，只能写「当前最好已知方案」，不能写成「最优」。

**门禁 W1 / W2**：

- `W1`（证据大纲）：写正文前先过审，防止写完全文才发现结论没证据；
- `W2`（论文终检）：排版、引用、数值全部校验通过，才算完成。

---

## 第 4 步：五个质检门禁速查

| 门禁 | 名称 | 什么时候过 | 卡住怎么办 |
| --- | --- | --- | --- |
| M1 | 建模终检 | 建模完成后 | 回建模手改模型 |
| P1 | 最小可运行 | 编程刚开始 | 修代码，或携报错回建模手 |
| P2 | 编程终检 | 全部算完、出图后 | 修代码重跑，不能进论文 |
| W1 | 证据大纲 | 写正文前 | 补齐证据再写 |
| W2 | 论文终检 | 论文校验后 | 改论文对应处 |

**规则**：某个门禁 FAIL → 回到它对应的那一段修正，**已经通过的阶段不重跑**。Claude 不会拿失败结论硬往下走。

---

## 第 5 步：中途要改东西，分快慢

中途或事后要改时，Claude 会先给你一个「成本单」，说清是哪种改法再动手：

| 改什么 | 做法 | 快慢 |
| --- | --- | --- |
| 只改措辞、结构、排版（数字不变） | 直接改对应段落，快速校验 | 几分钟 |
| 改某个数字或图表 | 重跑对应的求解脚本，只复核相关段落 | 中等 |
| 换模型、改假设、改求解路线 | 全流程门禁重走一遍 | 慢 |

---

## 第 6 步：怎么算「完成了」

- 题意、代码、公式、结果对得上；
- 所有数值来自真实运行结果，并且**能复现**（换台机器也能重算）；
- 论文里每个结论都有对应证据；
- 论文与结果同源，没有编的数据。

以上全部闭合，Claude 才会说「完成了」。

---

## 全程底线（四条不变量）

遇到看不懂 Claude 为什么「轴」时，多半是卡在这四条上：

1. **不偷偷改题**：评价对象、范围、量词、口径都不能静默变。
2. **关键假设必须明说**：有多种合理解释时并列讲清楚，不把「输出模板」当答案。
3. **代理模型只用于搜索**：最终结论必须由题目支持的严格判据验证。
4. **所有数值来自真实运行**：证据不足时就给条件结论 / 区间，不硬说完整解决。

---

## 目录约定（一句话）

题目和附件放在你的项目目录（`PROJECT_ROOT`），所有产物（代码、结果、图、论文）也只写在项目目录；Skill 自带的资料目录只读，不会乱动。
