# Subagent 调度与阶段门禁

Subagent 是阶段内临时协作者，不是第四个固定角色。主 Agent 负责统筹、写入权威产物和处理返工；质检 Subagent 必须未参与被审产物的编写，并默认只读。

## 默认策略

1. 默认仅派发下表中的固定质检 Subagent；调研、原型和并行实验等可选协作默认关闭。
2. 只有用户明确启用具体任务或类别时才派发可选 Subagent。用户未选择时不要反复询问，也不要暂停主流程等待授权。
3. 用户可随时增加、缩小或关闭可选协作范围；未明确启用的类别始终保持关闭。
4. 可选 Subagent 只返回范围、输入、证据或实验产物、结论、未知项和建议，不直接修改权威交付物；主 Agent 负责取舍和整合。

示例：`额外启用官方规则、附件盘点和文献调研 Subagent`、`只启用算法原型 Subagent`、`除固定质检外不使用其他 Subagent`。

## 强制原则

1. 禁止等全流程结束后才首次派发质检 Subagent；在下表规定的节点立即验收，未通过不得进入后续高成本工作。
2. 作者自检、脚本校验和独立验收三者不能互相替代。已有脚本负责机械检查，Subagent 负责独立复现、语义和证据审查。
3. 质检 Subagent 不直接修改固定交付物，只返回带证据的问题；原阶段执行者修正后，由未参与修正的质检 Subagent 复验。
4. 被验收的输入、模型、代码、结果或论文发生实质变化时，相关 `PASS` 立即失效；失效范围按论文手变更分级（论述/格式、数字/结果、模型/方法）划定，不默认全量失效。
5. 单阶段任务只运行该阶段的门禁，不强制拉起完整三阶段。
6. 运行环境没有 Subagent 能力时，继续运行确定性脚本并明确报告“独立验收未完成”，最终状态只能是 `BLOCKED` 或受限交付；不得声称全部门禁通过或完整完成。
7. `W2` 终审只在论文冻结后派发一次；迭代期修改论文不重发全量终审，返工限制在受影响正文段并重跑对应确定性门禁。终审后论文发生实质变化时，按变更分级重派受影响门禁。

## 固定门禁

| 门禁 | 派发时机 | 质检重点 | 通过后才能 |
|---|---|---|---|
| `M1` 建模终检 | 两个建模产物完成作者自检后 | 子问题覆盖、完成模式分类、假设/公式/单位/约束、可实现性、验证方案；领域关系→数学映射、四类自由度、新增/重复对象相对关系、聚合假设反转；模型适用性表、检索证据、参数来源、适用域、主分析窗口冻结；每题 `算法双源对照` 闭环 | 进入编程或交付建模产物 |
| `P1` 最小可运行结果 | 数据读取、预处理和核心求解链首次跑通后 | 从 `PROJECT_ROOT` 执行最小命令；核对真实输入或等价小实例、退出码、关键结果、单位、范围、约束和模型合同 | 开始全量计算、正式出图和参数扫描 |
| `P2` 编程终检 | 代码、结果表、创新证据清单、竞争性搜索账本（如有）、候选证据池、图表论证清单和复现清单冻结后 | 独立复现、输入哈希、种子、边界与量纲；核心反演/估计的任务特异回收或辨识性验证；多口径差异与不确定性账本；逐项核对创新证据；竞赛型再核对 `decision_space_audit`、`freedom_ref`、内部标尺、结构/表示挑战、incumbent 晋升、预算和停止证书 | 进入论文阶段或交付编程产物 |
| `W1` 证据大纲 | 主张—证据映射和论文大纲完成后 | 每个子问题的结论都有精确证据；创新表述只来自 `ADOPTED`；竞赛型的“最优/当前最好已知”措辞与停止证书一致 | 开始长篇正文和排版 |
| `W2` 论文终检 | 用户要求的全部论文格式及各自确定性门禁完成后 | 先运行确定性终审 lint（数字↔`results` 同源、关键口径锚点、占位符、双重编号；项目未建或非 0 即 `FAIL`，按 `roles/论文手/references/终审清单.md` 返回）；按终审清单 B 类逐项核对假设三档引证、反向锚点与定性结论数字锚点；再核对当届规则、主张—证据、数值与单位、竞赛型结论强度、图表引用、文献和实际渲染；同时生成两种格式时再检查 Word/LaTeX 一致性 | 宣布完整完成并交付论文 |

`P1` 是纵向切片，不要求完整候选证据池、敏感性分析或最终性能。`W1` 是内部检查，不新增固定交付物。每个阶段可由同一名始终未参与编写和修正的质检 Subagent 连续执行中途门禁与终检；不要为每个函数、每张图或每个段落重复派发。

## 派发提示词最小内容

主 Agent 派发固定质检 Subagent（`M1/P1/P2/W1/W2`，含复验与变更后重派）时，派发提示词**必须包含**以下全部内容，缺一不可；本表只约束派发提示词必须携带的条款，门禁本身的验收范围见上表各行。

### 通用（所有门禁必带）

1. **输入快照锚点**：全部被审产物与只读附件给出 SHA-256（或版本号），供回执「输入快照」核对；只给路径不算。
2. **模板来源**：竞赛、届次与硬约束（正文页数、摘要页、模板）注明已核验来源（2026 当届官方 URL 或用户提供件）；不得用 skill 默认值冒充官方值。
3. **回执格式**：按「固定回执」六项返回（范围/输入快照/状态/证据/发现 P0P1P2/返工）。
4. **不预判通过**：期望数值可作验收条款列出（数字同源要求核对一致性），但不得预判"已通过"或"主 Agent 认为正确"。

### 门禁必带（该门禁质检重点的强制落地）

| 门禁 | 派发提示词必带条款 |
|---|---|
| `M1` | 每题领域对象/关系→数学映射、量值/时序/结构/信息四类自由度、新增/重复对象相对关系、聚合表达的隐含假设与最小替代表示；每题算法双源对照闭环；模型适用性表及检索记录；模型形式与关键参数来源；文献适用域与题目域对照；主分析窗口和排除规则在最终答案出现前按独立标准冻结；事后变更保留前后结果并标为探索性分析。缺可核验产物即 `FAIL`，不以“已读文件”自述代替证据 |
| `P1` | 从 `PROJECT_ROOT` 执行的最小命令与退出码、真实输入或等价小实例、模型合同、单位与量纲 |
| `P2` | 独立复现与输入哈希、种子、边界与量纲；核心反演/估计的任务特异回收或辨识性验证；随机、数值、参数和模型形式不确定性账本；同数据多口径比较已处理协方差或明确无法估计；逐项核对创新证据；竞赛型再带账本逐字段、`decision_space_audit`、表示挑战 `freedom_ref` 与 `source_reconciliation` |
| `W1` | 每个子问题结论有精确证据路径、创新表述只来自 `ADOPTED`、竞赛型"最优/当前最好已知"措辞与停止证书一致 |
| `W2` | 实际运行终审 lint 并报告命令与退出码；按 `终审清单.md` 核对假设引证、反向锚点、定性结论数字锚点，以及机制归因的解析尺度/敏感性/反事实证据；正文区分随机、数值、参数和模型形式不确定性，不把模型差异写成测量修正或已证物理效应。新增引用须核验原始出版页；实质检查优先于格式与渲染抽检 |

### 复验 / 变更后重派附加

- **复验冻结**：复验时附"只复核列出的变更范围，未变部分仅抽查"，并把未变项逐条列出冻结；终审清单 C1–C6（AI 错误扫描）不受此冻结，必须全文执行。
- **变更分级声明**：被审产物实质变化后重派时，主 Agent 必须先做**变更分级**（论述/格式、数字/结果、模型/方法），在派发提示词中声明受影响范围与对应复验范围；未声明范围的变更重派视为不合规。

## 派发输入

只提供完成当前验收所需的原始证据：

- 用户要求、题目和只读附件路径。
- 当前门禁的验收条款和权威产物路径。
- 全部被审产物与只读附件的 SHA-256（或版本号）、官方规则来源、关键命令与日志。输入快照锚点与派发必带条款见「派发提示词最小内容」。
- 上一门禁回执；复验时再提供原问题及修正证据。

不要先告诉质检 Subagent“主 Agent 认为已经正确”，也不要给出期望的通过结论。质检范围外的历史对话不传入，避免结论污染。

## 固定回执

质检 Subagent 只返回：

1. `范围`：本次检查的门禁和未覆盖内容。
2. `输入快照`：路径、版本或 SHA-256。
3. `状态`：`PASS`、`FAIL` 或 `BLOCKED`。
4. `证据`：来源 URL、命令、退出码、文件位置、页码或关键数值。
5. `发现`：按 `P0`（正确性/官方硬约束）、`P1`（复现/一致性/关键质量）、`P2`（非阻塞改进）列出。
6. `返工`：应回到的角色、必须修正项和复验入口。

存在未解决的 `P0` 或 `P1` 时只能返回 `FAIL`；缺少依赖、权限、输入或可验证证据时返回 `BLOCKED`。主 Agent 不得把 `FAIL` 改写成通过。

## 用户可选协作（默认关闭）

| 任务 | 触发条件 | Subagent 输出 | 并行与边界 |
|---|---|---|---|
| 当届官方规则核验 | 竞赛、届次或模板尚未核验 | 官方 URL、适用届次（2026）、硬约束、模板路径与哈希、冲突和未知项 | 只检索 2026 当届官方模板/规则，不检索其他届次、年份与评阅要点；可与附件盘点并行；论文构建必须等待 |
| 数据附件盘点 | 多附件、复杂 PDF/Excel 或字段较多 | 文件哈希、工作表、行列、首末行、字段、单位、缺失和异常 | 只读；模型选择须等待关键数据事实 |
| 文献与模型族调研 | 主张、关键词或候选模型族已经明确 | 题名、作者、年份、DOI/出版页、理论公式、适用条件、所需数据和失败风险 | 按主张簇或模型族拆分；不要按搜索引擎拆分，最终模型取舍仍由主 Agent 完成 |
| 隔离算法原型 | 某个候选算法的可实现性、接口或复杂度需要验证 | 独立目录中的最小代码、运行命令、真实输出、限制和未解决问题 | 不修改权威代码；原型通过后由主 Agent 决定是否整合 |
| 独立实验批次 | 模型、指标和参数范围已经冻结，实验之间互不依赖 | 参数、种子、命令、结果文件、耗时和失败记录 | 可并行敏感性、消融或边界实验；不得边改模型边跑实验 |
| Python/MATLAB 对照实现 | 用户明确要求双语言或需要验证跨语言一致性 | 各自隔离的实现、命令、环境、关键数值和差异 | 使用同一模型合同和输入输出；主 Agent 统一权威结果 |
| 术语与英文表达核验 | 专业领域术语较多或需核验英文摘要/术语表述 | 术语对照、符号与单位冲突、建议修改位置和来源 | 只提供建议，不分章节并写论文 |

## 不委派或不并行

- 不让多个 Agent 同时修改 `题目分析报告.md`、`术语表格.md`、权威代码、结果或论文正文。
- 不按章节多人并写论文，不分别生成互不共享正文的 Word 与 LaTeX。
- 不把模型取舍、假设与阈值裁决、跨题耦合、用户授权和最终交付范围交给任何 Subagent。
- 依赖检查、哈希、编译、DPI、SVG 文本和文档结构等已有脚本覆盖的机械任务直接运行脚本，不再增加 Subagent。
