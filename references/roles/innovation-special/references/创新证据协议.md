# 创新证据协议

## 固定清单

编程阶段创建 `PROJECT_ROOT/results/创新证据清单.json`。没有创新时使用空 `items`，不得为了填表制造创新。

```json
{
  "schema_version": 1,
  "items": []
}
```

## 通用字段

每个候选包含：

```json
{
  "innovation_id": "Q2-I1",
  "question_id": "q2",
  "status": "HYPOTHESIS",
  "innovation_type": "model_structure",
  "source_lens": "feedback",
  "domain_tension": "回收件会改变后续装配质量",
  "baseline": "单次流转期望成本模型",
  "baseline_limitation": "截断回流反馈",
  "proposed_change": "稳态质量流不动点",
  "mechanism": "回收质量与装配缺陷率相互反馈",
  "competitive_relevance": "high",
  "failure_boundary": "拆解件不回流时退化为基线",
  "evidence_files": []
}
```

`competitive_relevance` 在竞赛型子问题中必填，取 `high/medium/low`。高竞争价值候选只有在最小原型或硬约束证据表明确实不值得继续时才能 `DROPPED`，并增加：

```json
{
  "drop_evidence": {
    "kind": "prototype",
    "summary": "原型在相同预算下被 incumbent 支配",
    "evidence_files": ["results/q4_candidate_compare.json"]
  }
}
```

`kind` 只能为 `prototype` 或 `hard_constraint`。预算不足不是 `DROPPED` 证据：保持 `HYPOTHESIS`，并把候选登记到 `竞争性搜索账本.json` 的 `untested_frontiers`。

允许的 `innovation_type`：

`problem_reframing`、`model_simplification`、`physical_simplification`、`geometric_simplification`、`model_structure`、`cross_question`、`algorithm_simplification`、`solver_improvement`、`information_design`、`uncertainty`、`theoretical`、`decision_rule`。

## VERIFIED/ADOPTED 附加字段

必须提供：

- `code_entry`：`相对路径.py:函数或类`，纯证明创新可省略。
- `reproduce_command`：从 `PROJECT_ROOT` 执行的命令。
- `evidence_files`：实际存在的结果、证明或日志。
- `verification`：验证类型、合理基线、指标、结果和限制。
- `paper_claim`：允许论文使用的克制表述。

若是纯理论创新，必须提供 `proof_file`；若是模型、物理或几何简化，还必须提供 `simplification`：

```json
{
  "original_model": "三维轴对称实体",
  "decision_quantity": "遮挡截面积",
  "preserved_property": "绕轴旋转下的截面半径",
  "discarded_effect": "非轴对称扰动",
  "mapping": "映射到母线平面",
  "proof_level": "G1",
  "proof_file": "results/proofs/q2_axisymmetry.md",
  "error_or_bound": "精确等价，误差为 0",
  "counterexample_test": "非轴对称扰动不适用",
  "failure_condition": "几何失去轴对称性"
}
```

其中 G1 表示严格等价，G2 表示保守界，G3 表示可控近似，G4 表示经验降阶。模型简化不能只报告维度下降，还要说明保持的目标、可行性或决策，以及误差或最优性损失。

算法简化和求解改进必须提供 `solver_route`，说明问题类别、合理基线、真实瓶颈和预算公平性。只有局部最优或随机性可能影响结论时，才设置 `multi_solver_trigger`。

不确定性创新必须提供 `uncertainty_contract`：

```json
{
  "uncertain_parameters": ["p1", "p2"],
  "joint_set_or_distribution": "联合置信域、后验样本或有依据的场景分布",
  "coverage_or_calibration": "联合覆盖率或校准方式",
  "decision_metric": "决策翻转率、后悔值或约束违反概率",
  "evaluation_method": "联合采样、鲁棒优化或场景求解",
  "limitations": "相关性、样本量和外推限制"
}
```

多个边际区间不自动构成联合置信域；只计算“全部下界”和“全部上界”不得直接称为联合最坏情形，除非证明目标和决策对全部参数具有相应单调性。

### 自由参数伦理字段（本地 P10，挂 P2）

模型结构、物理/几何简化类创新的 `VERIFIED/ADOPTED` 项，若其机制引入无直接文献/物理来源的自由参数，必须提供 `parameter_rationale` 四字段；缺任一 → 审计员打回：

```json
{
  "parameter_rationale": {
    "physical_meaning": "该参数代表的物理量及其预期范围；若模型未引入自由参数，写「未引入无文献依据的自由参数」",
    "residual_contribution": "无它时残差 / 加后减少量 / 是否超噪声底 2σ（2σ 为默认可覆盖阈值）",
    "lower_level_explanation": "残差能否用偏振、衬底 ε∞、界面粗糙度等更底层物理假设解释",
    "degeneracy_check": "是否与既有参数退化，辨识性结论"
  }
}
```

若模型未引入自由参数，四字段仍须存在：`physical_meaning` 写明「未引入无文献依据的自由参数」，其余写「不适用（无自由参数）」。**守卫（总闸优先）**：结构矛盾存在时，「加参数未过 2σ」不得成为跳过高阶解释的依据。

跨问统一创新必须给出至少两个不同的 `related_questions`，并说明共享状态、信息、约束或目标，不能只在结论中并列引用多个小问。

## 机制主张四重锁定（本地 P7）

任何「机制 X 显著」或「因此必须升级模型」的结论，必须同时满足以下四重锁定，缺一不可：

1. **矛盾锁定**：低阶模型失败的量化证据（RMSE 超过噪声底 2σ，或残差在异常区呈系统结构）。
2. **判据锁定**：判据量超过阈值（默认 ρ>0.1、F>1，可被题目精度覆盖）。
3. **复现锁定**：高阶模型复现异常特征（默认谷位差 < 0.5 cm⁻¹，阈值可覆盖）。
4. **来源锁定**：机制能落到教科书级物理或盲做允许的赛前文献（菲涅耳、Airy、Drude 等），**禁止自造机制冒充**。

缺任一锁 → 该主张在论文中自动降级为「推测」，句末必须加注「需进一步验证」。审计员检查 `创新证据清单.json` 时，若 `VERIFIED/ADOPTED` 的机制类主张缺少任一锁的数值引用，直接打回。

### 判据通过后的强制路径切换（本地 P7 附加）

四重锁定**全部通过**时，主张不能停在「判据成立 + 基频稳健」。判据数值是**呈堂证据，不是自动判决**：

1. **必须解释**：运行高阶模型对异常特征做全阶拟合（如 Airy 全阶拟合谷位、谷宽、角度偏移），比较高阶 `d_high` 与低阶 `d_low`。这是物理判据的必然要求，不是可选步骤。
2. **辨识性护栏**：全阶拟合必须通过辨识性检查——参数不退化（无 scale/offset 吸收对比度导致的形状失灵）、残差结构合理、拟合不确定度不吞没效应量。**辨识性不通过时，全阶不产出主结果**，两条绕行路均禁止：
   - 禁止「基频稳健 → 跳过全阶」；
   - 禁止「全阶拟合失败 → 回到低阶并宣称已解释」；
   - 正确动作：执行预判摘要已承诺的失败出口——低阶与高阶**同时**报告为不一致，输出带分歧的可辨识带，自动切换分歧报告模式，不阻塞、不等用户。
3. 只有闭环成功（辨识性检查通过 + P6 三选二完成）后，机制主张才可写为 `ADOPTED`；闭环失败时只能以分歧报告表述，禁止以"已解释"口吻写入。缺路径切换或缺护栏 → 审计员打回。

## 状态门禁

- `HYPOTHESIS` 不要求证据文件，但不得写 `paper_claim` 为已完成语气。
- `PROTOTYPED` 至少有代码入口或证明草稿，以及一个原型产物。
- `VERIFIED` 必须有完整证据、验证和失效边界。
- `ADOPTED` 还必须说明它怎样改变题目答案，并给出克制的论文主张。
- `DROPPED` 必须有 `drop_reason`，不得保留宣传性主张。
- `competitive_relevance: high` 的 `DROPPED` 还必须有可追溯 `drop_evidence`；主观判断不能替代原型或硬约束证据。

图表可以是证据文件之一，但不能代替公式、证明、结果或代码。
