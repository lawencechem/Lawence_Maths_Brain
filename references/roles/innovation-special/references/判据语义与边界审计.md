# 判据语义与边界审计

## 目标

优化器会忠实放大模型合同中的任何宽松。当延展对象被缩成一个代表点、全称量词被改成存在量词，或程序用 `clip/max/min/where` 静默规定了题面未给出的边界行为时，“更优”可能只是对替代判据的利用。本审计先锁定题意合同，再允许搜索和创新。

本文不规定“覆盖必须检查全表面”或“状态到达边界必须终止”。正确合同由题面、数学推论、有据的外部机理和明示的建模选择决定；禁止的是无来源的静默改写。

## 一、判据语义合同

对每个驱动结论的判据，在建模报告中写明：

| 字段 | 必答问题 |
|---|---|
| 主体 | 谁对谁产生作用，或谁被评价？ |
| 对象范围 | 点、线、面、体、时间区间、人群或数据总体中的哪一部分？ |
| 量词 | 存在一个、任意一个、全部、至少某比例、平均或概率超阈值？ |
| 跨对象聚合 | 多目标、多威胁、多主体或多任务之间取求和、并集、交集、全部、任一、平均、比例还是最坏情形？ |
| 跨域聚合 | 瞬时/单样本判据怎样跨时间、空间或样本合成为总指标？ |
| 区分反例 | 哪个最小场景会让两个合理候选口径给出不同判断或方案排序？ |
| 接受测试 | 最终代码中哪个可执行布尔/数值判据实现了上述语义？ |
| 来源 | `PROBLEM` / `DERIVED` / `EXTERNAL` / `MODELING_CHOICE`，并给原文、推导、文献或选择理由。 |

题面给出的尺寸、区域和对象类型必须进入验收判据，或有证据地说明它对结论无关。代表点、代表个体、平均值或代理指标代替题意对象时，它是“判据级简化”，不是普通的参数灵敏度。

输出模板只定义需要填写的字段，不能自动定义优化目标。出现“对象编号、分配对象、每项时长/得分”等列时，必须回到题面主语判断整体指标；例如逐对象填表并不能证明总目标应取逐对象得分之和。

- 能证明等价：记录等价证明。
- 是保守边界：标明上界/下界方向和适用条件。
- 只是加速用代理：允许用于搜索，但不能用它验收最终方案。
- 题意存在多种合理解释：并列合同，做反事实对照；若结论依赖解释，交付条件结论或区间，不静默选择最宽松的一个。

## 二、状态域与边界条件

对每个在评价时窗内演化的核心状态，记录状态域、演化律、可能到达的边界、到达后行为及来源。

边界后行为只能来自：

1. 题面明示；
2. 已写出的数学定义或必然推论；
3. 与题目尺度和工况匹配的外部机理/文献；
4. 明示标为 `MODELING_CHOICE` 且已做替代边界对照的建模选择。

任何 `clip`、`maximum`、`minimum`、饱和、反射、吸收、落地停止、越界继续或寿命截断都必须进入此表。若状态在评价时窗内到达一个题面未规定的边界，该候选标记为 `UNCERTIFIED`；先补边界机理或交付多边界条件的分歧结果，不得默认夹取后继续计分。

如果确认评价时窗内不会达到任何有效域边界，可将边界表留空，但必须给出 `no_boundary_basis`。

## 三、优化器漏洞计审

搜索器可以使用低成本代理判据生成候选，但 incumbent 必须在题意支持的最严格合同或已验证的高保真近似下重新计分。下列任一信号触发对抗性复核：

- 候选贴着状态域、时间窗、寿命、容量、几何或变量边界；
- 优势大部分来自某个新加的代理、裁剪、饱和或边界后行为；
- 新机制带来会改变方案排序、可行性或核心结论的实质改善；
- 小扰动代理参数或边界处理即导致排序翻转；
- 代理指标已饱和，但高保真判据的余量未证明。

复核至少输出：严格判据得分、活跃约束、评价时窗内的边界穿越、代理与严格判据差值、局部扰动和优势是否保留。不用“改善超过 2 倍”这类固定阈值；触发应由决策影响、边界信号和事先声明的裕度决定。

## 四、门禁

- `M1`：先独立复述每问目标，并用区分反例审查“主体—对象范围—量词—跨对象聚合—跨域聚合—接受测试—来源”；语义失败立即 `FAIL`，不继续用格式或次要字段稀释问题。所有实际可达的核心状态再核对域与边界处理。
- `P1`：用一个手算、精确小例或高保真对照核对判据实现；若搜索使用代理，同时计算代理—严格判据差值。
- `P2`：对最终 incumbent 执行严格合同认证和边界穿越审计。`strict_contract_pass != true` 或证据缺失时，不得关闭竞争搜索。
- `W1/W2`：正文的对象范围、量词、边界条件和数值实现必须一致；只有通过严格合同认证的机制才能写为创新。

## 五、竞争性账本副本

竞争性子问题在 `decision_space_audit` 之外必须写入 `model_contract_audit`：

```json
{
  "model_contract_audit": {
    "criterion_semantics": {
      "subject": "被评价的主体与作用对象",
      "object_extent": "题面对象的空间/时间/样本范围",
      "quantifier": "全部/存在/比例/平均等的题意量词",
      "across_entities": "多对象之间的求和/并集/交集/全部/任一/平均/最坏情形等聚合",
      "across_domain": "跨时间/空间/样本的测度、累计、峰值或概率等聚合",
      "distinguishing_counterexample": "能区分候选合同的最小反例",
      "acceptance_test": "可执行的严格判据",
      "source": "PROBLEM",
      "basis": "题面原文/推导/外部来源/建模选择理由"
    },
    "state_boundary_conditions": [],
    "no_boundary_basis": "评价时窗内所有核心状态不达有效域边界",
    "uses_proxy_or_surrogate": false,
    "incumbent_certification": {
      "strict_contract_pass": true,
      "boundary_crossings_checked": true,
      "active_constraints_checked": true,
      "proxy_gap_status": "NOT_USED",
      "evidence_files": ["results/q4_contract_check.json"]
    }
  }
}
```

`across_entities`、`across_domain` 与 `distinguishing_counterexample` 在存在多个对象或多个合理聚合口径时为必填；单对象且聚合无歧义时可写 `NOT_APPLICABLE` 并给一句依据。为兼容旧账本，机械审计器可暂不要求旧记录补字段，但新的 `M1` 不得跳过这一语义检查。

若 `uses_proxy_or_surrogate=true`，还必须填 `proxy_relation`、`strict_contract` 和 `proxy_validation_evidence_files`。`proxy_gap_status` 只允许 `NOT_USED/PASS/FAIL/UNRESOLVED`；代理已使用时不能填 `NOT_USED`，`FAIL/UNRESOLVED` 均不允许 incumbent 通过。

`criterion_semantics.source=MODELING_CHOICE` 时还必须提供 `alternative_contract` 与 `alternative_evidence_files`；某个边界行为为 `MODELING_CHOICE` 时必须提供 `alternative_behavior` 与 `alternative_evidence_files`。只写“更符合物理”不构成对照证据。
