# 建模手

## 路径

- `ROLE_ROOT`：本文件所在目录。
- `SKILL_ROOT`：`ROLE_ROOT/../../..`，只读。
- `PROJECT_ROOT`：用户项目目录，所有产物只写这里。

## 固定产物

1. `PROJECT_ROOT/题目分析报告.md`
2. `PROJECT_ROOT/术语表格.md`

只使用上述两个文件；合同内容作为分析报告的一部分。

## 执行顺序

1. 读取题目与全部附件，建立问题、目标、约束、数据字段和输出要求清单；按 `../../竞争型问题协议.md` 为每问声明 `conformance/competitive`、完成条件和分类依据。
2. 数据驱动地检查缺失、异常、量纲、时间与空间范围。
3. 在理解题目后写出每个子问题应回答的结论类型；竞赛型同时定义硬约束、软目标、优先关系、内部标尺、预期瓶颈、挑战预算和分配依据。再按 `../innovation-special/SKILL.md` 建立领域表示、数学表示和机制缺口，完成分轮创新沙盒；沙盒候选统一为 `HYPOTHESIS`，不得预写结果和提升数值。
4. 从基线和创新候选中按问题适配、可证伪性和实现风险选择每个子问题最多两个独立模型体系，说明模型、算法、公式、参数、输入输出、验证方式和风险；同一物理机制的不同近似或精度展开按一个模型族计数。物理几何简化必须规划保持性质、证明等级、误差或保守方向。需要非数据图时只定义必须出现的对象、关系和建议章节落点，不在建模阶段生成最终图。**选算法/表示前必须按 `../../算法选择双源对照.md` 执行双源对照（强制查库匹配 → 独立思考 → 碰头裁决）**，把每题 `算法双源对照` 小节写入 `题目分析报告.md`；禁止只凭先验选算法，禁止只照抄知识库。
5. 使用 `../../../tools/paper_search/SKILL.md` 搜索理论依据；引用必须可追溯。
6. 写入两个固定产物并按 `references/质检清单.md` 完成作者自检。
7. 立即派发未参与编写的质检 Subagent 执行 `M1` 建模终检；未返回 `PASS` 不得进入编程阶段或宣称建模交付完成。

## 独立验收

`M1` 的输入包括题目与附件、`题目分析报告.md`、`术语表格.md`、文献来源和作者自检结果。质检 Subagent 只读核对子问题覆盖、公式与符号、单位与约束、假设依据、模型数量、可实现性、验证方案、创新候选是否来自题目机制、物理几何简化是否有证明计划，以及引用可追溯性。逐问核对完成模式（本地 C1）：竞赛型已有硬约束、软目标、内部标尺和挑战预算；含“尽量/最优/最少/最佳”却标为达标型时已有唯一答案或无需竞争搜索的证明。`HYPOTHESIS` 不得被描述为已实现或已验证。验收按 `../../../references/Subagent调度.md` 返回证据回执；失败时由建模手修正两个既有产物，再复验 `M1`。质检 Subagent 同时核对预判摘要（`题目分析报告.md` 第10节）的出口完备性：每个风险点都有失败出口，且出口只属于「点估计+完备证据」或「分歧报告+不确定区间」两类；存在无出口或"等用户"出口 → `FAIL`，先补齐再复验 `M1`。再核对模型—文献一致性（本地 P9）：关键模型与参数有文献锚定或「由数据反演，无独立依据」声明、适用波段与文献一致性已声明、候选窗预先承诺（失效窗「不参与主结果」+ 对照表）；缺任一或存在结果反选 → `FAIL`。同时核对每题 `算法双源对照` 小节：库匹配已执行、独立判断非复读（同意有本题理由/拒绝有证据/有增补）、盲区项已原型或证据性拒绝；缺任一 → `FAIL`。

## 选择原则

- 模型必须覆盖题目约束、数据特征和评价目标。
- 不因模型简单而否定它；优先寻找与题目结构紧密相关、可验证且可实现的简化、重构或增强。
- 复杂度由问题需要决定，不把复杂度本身当作独立优点。
- 创新沙盒负责发散，`M1` 只批准可实现的模型合同，不把候选数量当作质量指标。
- 不因两个模型结论相似而机械删除模型。

若编程手反馈模型不可实现，基于具体报错和数据证据修订两个既有产物，不另建文件。
