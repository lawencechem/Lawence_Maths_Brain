# 建模手工作流程

## 零、目标语义卡先行

开始时只读取题目和必要附件，按 `目标语义卡.md` 逐问写出日常语言任务、瞬时/单样本成功条件、跨对象聚合、跨时间/空间/样本聚合、输出合同和区分反例。此时不读取算法库、创新协议、竞争协议、编程手或论文手资料。

语义卡为 `LOCKED` 后才继续；若为 `PARALLEL_CONTRACTS`，后续模型必须保留各口径并做对照，不能在代码里暗选一个。附件模板只定义输出字段，不定义目标函数。

## 一、读题与附件

1. 枚举题目、附件、数据表、图片和模板，记录文件哈希或明确版本。
2. 按子问题列出目标、约束、输入、输出和评价口径。
3. 检查数据字段、单位、缺失、异常、重复、时间顺序和空间关系。
4. 无法确认的事实写成待确认项，不自行补造。

### 异常值处理协议（本地化·两段式）

数据检查发现任何偏离预期形态的点/区间（深谷、尖峰、突变沿）时，执行以下两段式，**禁止直接剔除或滑动窗口**。

**第一段：统计显著性门控（本地 P0）**
- 取异常点邻域（±5 个采样点）的残差标准差 σ_local（代码中必须可复现，禁止口头估计）。
- 异常偏离 < 3σ_local → 判为「统计不显著」，按随机噪声处理，剔除并记录阈值与数量，**结束流程**。
- 异常偏离 ≥ 3σ_local → 进入第二段。

**第二段：物理归因分叉（本地 P1）**
- 归因为「标定截断/已知伪迹」（如首行 R=0）→ 允许剔除，记录依据。
- 归因为「高阶机制签名」（如反射率深谷、非正弦干涉、突变沿）→ **禁止剔除、禁止滑动窗口避开**，必须触发「模型升级流程」（后续建模必须用高阶模型去拟合它）。
- 无法明确归因 → 按「高阶机制签名」处理（保留数据、尝试升级），并在 `题目分析报告.md` 中标注「未归因异常」。

## 二、理解后形成结论目标

先回答“题目要求最终说明什么”，再讨论模型。结论目标应描述输出类型和评价标准，不预写数值结果。

题目确有开放优化或方案竞争时才读取 `../../../竞争型问题协议.md`。`conformance` 写清答案合同；`competitive` 分开写硬约束与软目标，并规划内部标尺、结构性挑战和预算。可证明最优的优化题仍标为 `competitive`，以最优性证书结束。

示例：

- 输出满足全部容量与时间窗约束的配送方案，并比较成本和稳定性。
- 输出未来各期预测及其不确定性，并用留出数据检验误差。

## 三、选择模型

每个子问题最多两个独立模型体系。模型数量包括主模型、并行对比模型或机理不同的串联阶段模型；灵敏度分析和误差检验不计作独立模型。

物理建模按“模型族”计数：若两光束干涉与多光束干涉共享同一物理机制和核心变量，只是反射阶次或精度不同，应视为同一模型族的基础版与扩展版。只有控制机理、状态变量、边界条件体系或求解目标发生实质变化时，才另计一个模型。

只有控制/策略、多对象、聚合表示或用户要求创新时，才按 `../../innovation-special/SKILL.md` 和 `../../innovation-special/references/决策空间完备性.md` 检查领域关系与自由度；普通闭合问题不强制创新沙盒和四类自由度表。触发创新时先找基础模型未表达的机制缺口，再做结构变换与反例，候选统一标记为 `HYPOTHESIS`，不预写结果。

选择时逐项核对：

- 是否表达题目中的关键结构和约束。
- 数据是否满足模型假设。
- 是否能由 Python 或 MATLAB 可靠实现。
- 是否有清晰的验证方案。
- 创新是否来自题目特有机制、严格简化、状态或决策重构、跨问统一、信息利用、求解结构或理论性质，而非简单改名。

避免直接套用通用模型冒充创新，也避免为了显得高级而拒绝更合适的简单模型。模型选择以问题适配、可验证和可实现为准。

### 算法双源对照（条件触发）

当算法陌生、表示选择会改变可行域/结果质量，或竞赛型问题需要结构挑战时，按 `../../../算法选择双源对照.md` 执行三步；简单闭合问题可直接说明选择理由，不生成固定表：

1. **定向查库匹配**：写明问题特征，打开 `../../../算法索引.md` 后只读取一个最相关的 `../../../../assets/*.md`；需要原文细节时只精读 `../../../../knowledge/算法大全_全文/` 对应章节，不遍历整个知识库。
2. **独立思考**：对着候选表写同意（给本题理由）/拒绝（给证据）/增补（库没有的题目特有候选），不得复读库的适用条件；全为照抄 → 判定被锚定，补独立理由后才能继续。
3. **碰头裁决**：三栏定案——双源共识采用；库有 AI 无（盲区）默认最小原型试算或证据性拒绝；AI 有库无保留候选并核对适用条件。

触发时把问题特征、库候选、独立判断和裁决写入报告；未触发时一两句说明直接方法为何足够。`M1` 只核对实际触发项，不因普通问题缺少对照表而失败。

### 物理与几何模型

出现质点、刚体、忽略阻力、三维转二维、实体转中心线、曲面转平面、凸包或等效形状时，按 `../../innovation-special/references/物理几何简化.md` 记录：

- 最终需要保持的物理量、几何性质或决策判定。
- 原始对象、简化映射和被忽略效应。
- 尺度比、无量纲参数或集合包含关系。
- `G1/G2/G3/G4` 证明等级及计划产物。
- 误差与决策阈值的关系、反例和失效条件。

图形只能解释证明，不得以“由图可知”替代推导。

## 四、搜索理论依据

独立初读和目标语义候选形成后、模型冻结前，按需读取 `../../../../tools/paper_search/SKILL.md`。先针对真实歧义、领域判据和机理搜索，再查模型参数与适用域；不在结尾用文献反向证明已经写死的模型。引用前检查原始出版页面，默认不检索赛后同题资料。

## 五、写交付物

### `题目分析报告.md`

核心内容包括：

1. 目标语义卡与题面依据
2. 子问题、输入输出、约束和必要数据检查
3. 假设、模型、算法、验证和失败条件
4. 实际使用的文献及适用域

仅在命中相应风险时追加竞争模式、决策空间、创新沙盒、物理几何简化、视觉论证和边界审计；不为保持固定章节编号填充空表。

存在 `competitive` 问题时，相关子问题再包含分类依据、硬约束、软目标、优先关系、内部标尺、预期瓶颈和挑战预算；`conformance` 问题只需写清答案合同与完成条件。

控制/策略、多对象或聚合表示触发决策空间审计时，记录会改变可行域或方案排序的领域关系、自由度和聚合假设；无触发信号时不要求四类自由度空表。

其中”编程依赖和候选图表”按 `../../../../references/视觉论证与配图策略.md` 写成视觉论证需求：逐题记录读者疑问、核心主张、证据来源、建议载体、必须出现的对象与关系以及建议章节落点。原始数据、过程和结果只是可能的证据来源，不预设每题必须生成三类图；机理、几何、流程、架构和拓扑图只给出数学语义与结构要求，不在此阶段绘制终稿。

**风险、反例与回退条件**：只记录最可能改变结论的实质风险，通常 1–3 个，不设数量配额。每个风险写清：

| 触发条件 | 应对方案 | 失败出口 |
|---|---|---|
| 什么证据/数值出现时该风险成立（必须可复核，禁止”可能影响精度”这类不可判定措辞） | 触发时实际执行的动作（具体到方法、数据、对比对象） | **不等于”方案成功”的陈述**，只允许两类：① 点估计 + 完备证据；② 分歧报告 + 不确定区间。**禁止”等用户”作为出口** |

- 写不出失败出口时，不得把该假设包装成完整解决；可保留为待验证假设或受限交付。
- 数值阈值必须来自题目、数据、物理或文献，不为了接近期望答案事后反选。

### `术语表格.md`

至少包括中文术语、英文术语、符号、定义、单位、首次出现位置和禁止混用的近义词。

## 六、M1 独立验收

两个文件完成作者自检后立即冻结输入快照，并按 `../../../../references/Subagent调度.md` 派发未参与编写的质检 Subagent。`M1` 未返回 `PASS` 时不得进入编程；质检发现问题后由建模手修正，产物变化会使原回执失效，必须复验。

## 七、反馈修正

编程手返回实现证据后，直接修订上述两个文件并说明变更，不创建同义版本文件。
