# 建模手质检清单

按优先级检查；第 1 组失败时立即返工，不继续用次要清单稀释核心错误。

## 1. 题意否决项

- [ ] 每问已有目标语义卡：一句话任务、评价主体、瞬时/单样本成功、跨对象聚合、跨时间/空间/样本聚合、输出合同、依据和状态。
- [ ] 已独立构造区分反例；多个合理口径给出不同判断或排序时，没有静默选择其中一个。
- [ ] 附件模板只用于确认输出字段，没有从“对象编号、分配、每项时长/得分”等列直接推导总目标函数。
- [ ] 题面主语、保护/评价对象、量词、目标函数和代码计划一致；语义未锁定时保留 `PARALLEL_CONTRACTS` 或受限交付。

## 2. 模型核心

- [ ] 已读题目和必要附件，输入保持只读；变量、参数、单位、目标函数和约束定义完整。
- [ ] 假设有题面、数学推论、领域文献或明示建模选择依据；代表点、代理和边界行为没有暗改题意。
- [ ] 模型可实现且有与结论风险相称的验证、反例、失败条件和回退路线。
- [ ] 文献检索发生在独立初读之后、模型冻结之前；只使用实际需要的来源并核验原始出版页。

## 3. 条件触发项

- [ ] 若为 `competitive`：已区分硬约束与软目标，写明内部标尺、挑战预算和停止条件；首个可行解不算完成。
- [ ] 若存在多对象/控制/聚合：已检查关键量值、时序、结构、信息自由度及对象相对关系；默认求和、平均、同步或固定分配已经反转挑战。
- [ ] 若使用代理或涉及覆盖/延展对象/动态边界：已定义严格合同、代理关系、状态域和边界来源。
- [ ] 若算法选择陌生或高影响：已定向读取一个相关算法资产，保留独立判断；没有遍历整个知识库或照抄候选。
- [ ] 若声称创新或物理几何简化：候选状态、证明/原型、适用域和失败边界有证据，不按数量凑项。

## 4. 交付

- [ ] 只做思路讨论时没有创建空表、账本或无关产物；完整流程只交付 `题目分析报告.md` 和 `术语表格.md`。
- [ ] 文件位于 `PROJECT_ROOT`，未覆盖输入附件或执行态 `SKILL_ROOT`。
- [ ] 固定产物已由未参与编写的质检 Subagent 执行 `M1`；回执为 `PASS`，通过后未发生未经复验的实质变化。
