# 编程手工作流程

## 一、读取输入

从 `PROJECT_ROOT` 读取题目附件、`题目分析报告.md` 和 `术语表格.md`。输入文件只读；输出写入新文件。

## 二、选择语言并动态检查依赖

根据用户要求、现有代码和模型函数选择 Python、MATLAB 或两者作为求解语言。只检查实际选中的功能。正式论文配图统一使用 Python/Matplotlib；MATLAB 求解结果先导出为可追溯 CSV/MAT，不调用 MATLAB 绘图作为第二套视觉后端。

Python：

```powershell
python ../scripts/check_env.py --features data visualization optimization
```

可选功能包括 `data`、`visualization`、`excel`、`optimization`、`integer-optimization`、`statistics`、`machine-learning`、`time-series`、`graph` 和 `image`。

MATLAB：

```matlab
addpath("../scripts");
report = check_matlab_env(["data", "optimization"]);
assert(report.ok, "缺少所选模型需要的 MATLAB 工具箱");
```

缺少依赖时报告精确名称，不自动改用另一个模型或语言。

## 三、实现与运行

1. 把数据读取、预处理、模型、验证、可视化和输出拆成清晰函数。
2. 随机算法显式设置种子。
3. 所有关键参数集中定义并写入复现清单。
4. 实际运行代码；禁止手写或伪造结果。
5. 检查约束可行性、数值范围、边界条件和验证指标。
6. 若模型本身矛盾，把实际报错和最小复现反馈给建模手。

基础模型必须先于创新原型完成。不得因为创新候选更醒目而跳过基线，也不得把计划中的蒙特卡洛、阻尼、求解器对照或灵敏度写进结果说明。

读取题目分析报告中的 `completion_mode`。达标型在答案合同与风险验证通过后收敛；竞赛型把本节得到的首个可行结果登记为 baseline/incumbent，不得直接进入论文阶段。

### 计算加速（按需）

- 估算计算量（`单步耗时 × 总时间步`），>5000 时间步或单段扫描 >30 s 时加载 `计算加速.md` 选路线。
- 默认路线：**跨时间步 numpy 向量化**（把 `(T, ...)` 数组组织成"步内串行、步间并行"，批量牛顿代替 brentq、碰撞窄相按候选对向量化），零依赖、通常 10~40×。
- 批规模 >1e4~1e5 且有 GPU 库（torch/cupy）时，把数组换 GPU 张量；否则用 `multiprocessing` 按核数切采样。
- **硬性要求**：加速后与串行或高保真基线按模型容差核对，并把一致性、容差依据与提速写入 `results/验证完备性.json`；不得因并行改变模型、约束或边界条件。

## 四、P1 最小可运行结果

完成数据读取、预处理和核心求解纵向切片后，在全量运行与正式出图前派发独立质检 Subagent：

1. 从 `PROJECT_ROOT` 执行一条最小命令。
2. 每个会驱动后续全量计算的模型族至少覆盖一个真实输入或结构等价小实例。
3. 核对退出码、输入到结果的追溯、单位、数值范围、关键约束和 `M1` 模型合同。
4. 实现问题返回编程手；公式、约束或参数合同问题携命令、堆栈和预期—实际证据返回建模手。

`P1` 未返回 `PASS` 不得继续全量计算、参数扫描和正式出图。它不要求三类图、完整敏感性分析或最终性能。

## 五、创新原型与证据

读取 `../../innovation-special/SKILL.md` 和 `../../innovation-special/references/创新证据协议.md`：

1. 创建 `results/创新证据清单.json`；没有适合采用的创新时保留空 `items`。
2. 从 `HYPOTHESIS` 中选择少量值得测试的候选，先实现最小原型，不按每问分配创新。
3. 对模型或算法候选使用合理基线、相同输入和公平预算；对简化候选提供等价证明、保守界或误差界。
4. 对采用候选执行消融、反例或失效边界测试，记录失败结果，不只保留最好一次。
5. 只有真实产物齐全时才能更新为 `VERIFIED`，只有改变题目答案或解释时才能更新为 `ADOPTED`。
6. 运行 `innovation_audit.py`；退出码非零时返回实现或建模阶段，不得用文字覆盖。

### 竞赛型挑战循环（条件触发）

存在 `competitive` 子问题时，读取 `../../../竞争型问题协议.md` 并创建 `results/竞争性搜索账本.json`：

1. 冻结 `P1` 后的可行 baseline，登记硬约束、软目标和当前 incumbent。
2. 用下界、精确小实例、Oracle、Pareto、合理基线或逐层决策空间建立至少一种内部标尺。
3. 诊断主要瓶颈，优先挑战目标口径、决策表示和结构分解，再考虑求解器；隔离运行，不直接改写权威主链。**决策表示/求解结构挑战前，先按 `../../../算法选择双源对照.md` 执行双源对照（强制查库匹配 → 独立思考 → 碰头裁决），把 `source_reconciliation` 写入该挑战条目；库有 AI 无的盲区项默认最小原型或证据性拒绝。**
4. 对预算内 `competitive_relevance: high` 的候选完成最小原型。无证据时保持 `HYPOTHESIS` 并登记未探索前沿，不得主观 `DROPPED`。
5. 每个挑战者先核对硬约束，再按既定目标口径公平比较；通过且更优才晋升 incumbent，并重跑受影响结果与门禁。
6. 仅以 `PROVEN_OPTIMAL/GAP_TARGET/BUDGET_EXHAUSTED/DIMINISHING_RETURNS/BLOCKED_BY_CONSTRAINT` 之一关闭挑战。
7. 运行 `../../innovation-special/scripts/challenge_audit.py`；未通过不得进入 P2。

## 六、视觉论证执行链

按 `../../../../references/视觉论证与配图策略.md` 执行“论证缺口→载体选择→候选生成→清单登记→文件审计→实际读图”的完整流程：

1. 从题目分析报告提取全部子问题并规范为 `q1…qN`，读取其中的视觉论证需求。
2. 先建立 `results/图表论证清单.json`；每个证据单元明确对应子问题、读者疑问、核心主张、证据来源、载体、视觉角色、章节落点和最终决策。
3. 文字、公式或表格更直接时不画图。数据图加载 `../../../../tools/figure/SKILL.md`；机理、几何、流程、架构和拓扑图加载 `../../../../tools/diagram/SKILL.md`。
4. 数据图、流程图、架构图和拓扑图统一走 Python：Matplotlib 负责最终绘制与导出，NetworkX 仅负责离散结构。连续二维/三维几何优先走 GeoGebra Classic；无法自动渲染时交付逐行指令和生成说明，Matplotlib 作为自动后备。
5. 数据图可沿用 `raw_qN_*`、`process_qN_*`、`result_qN_*` 来源标签；非数据图使用语义前缀。类别和图型不设配额，每张候选图都必须进入清单并明确 `KEEP/MERGE/APPENDIX/DROP`。
6. 所有正式候选图经 `../../../../tools/figure/scripts/export_figure.py` 同源导出 SVG 与至少 300 DPI PNG，显式设置最终尺寸并使用 `tight=False`。
7. 运行 `check_figure.py` 后，再运行 `python "<SKILL_ROOT>/references/roles/编程手/scripts/figure_audit.py" "<PROJECT_ROOT>/figures" --manifest "<PROJECT_ROOT>/results/图表论证清单.json" --questions q1 q2 ... qN --strict`。实际打开 PNG 和灰度预览；发现问题回到源代码修正并重新运行。

## 七、文件结构

```text
PROJECT_ROOT/
├── data/                         # 输入，只读
├── 题目分析报告.md               # 建模手产物，只读
├── 术语表格.md                   # 建模手产物，只读
├── 问题1_求解.py 或 问题1_求解.m
├── results/
│   ├── 问题1_结果.csv
│   ├── 题目指定结果.xlsx         # 仅题目要求或需保留模板时
│   ├── 创新证据清单.json         # 允许 items 为空
│   ├── 竞争性搜索账本.json       # 仅存在 competitive 子问题时
│   ├── 图表论证清单.json
│   └── 复现清单.json
└── figures/
    ├── raw_q1_* / process_q1_* / result_q1_*  # 可选的数据来源标签
    ├── mechanism_q1_* / geometry_q1_*          # 机理与几何图
    ├── flow_q1_* / architecture_q1_*           # 流程与架构图
    ├── topology_q1_*                            # 网络拓扑图
    └── 图表面板.html
```

同一图的 SVG、PNG 和灰度预览按 1 张逻辑图计数。图可以生成候选版本用于比较，但每个版本都必须登记用途和最终决策；不得为满足数量或题号覆盖生成无论证价值的图。

## 八、Excel

- 普通结果表优先 CSV。
- 题目要求 `.xlsx`、多工作表、公式或既有模板时使用 Excel。
- 读取 XLSX 时显式声明是否有表头；第一行就是数据时使用 `pandas.read_excel(..., header=None)` 或 `read_excel_rows(..., header=False)`，并核对首行、末行与预期行数。
- 模板结构和公式不随意修改，另存到 `PROJECT_ROOT/results/`。
- 公式工作簿使用 `../../../../tools/xlsx/scripts/recalc.py` 重算；失败或超时时原文件不应被覆盖。

## 九、复现清单

示例：

```powershell
python ../scripts/repro_manifest.py `
  --project-root "<PROJECT_ROOT>" `
  --input "<PROJECT_ROOT>/data/input.csv" `
  --seed 42 `
  --parameters '{"alpha":0.1,"max_iter":1000}' `
  --command "python 问题1_求解.py --seed 42" `
  --package numpy --package scipy
```

唯一复现命令必须从 `PROJECT_ROOT` 可直接执行，并生成与论文引用一致的表格和图。

## 十、P2 编程终检

代码、结果表、创新证据清单、竞争性搜索账本（如有）、候选证据池、图表论证清单和复现清单完成作者自检并冻结后，按 `../../../../references/Subagent调度.md` 派发独立质检 Subagent。质检者重跑唯一复现命令，核对哈希、环境、种子、参数、关键数值、约束、边界、量纲、统计计算和各子问题证据语义；重跑创新审计与条件触发的挑战审计，并核对每个 `ADOPTED` 项的实际实现、证明、公平基线、量化结果和失效边界，以及竞赛型问题的内部标尺、结构性挑战、预算与停止证书。带 `--manifest`、全部 `--questions` 的 `figure_audit.py --strict` 结果和实际 PNG/灰度预览作为证据输入。`P2` 未返回 `PASS` 不得进入论文阶段。
