# 验证完备性

目标：根据模型的真实失效风险选择验证，而不是让每篇论文机械拥有采样收敛、网格收敛、双参数灵敏度和多求解器。

## 一、先建立验证风险表

对每个核心结论记录：

| 字段 | 含义 |
|---|---|
| 结论 | 论文准备使用的数值、排序、策略或阈值 |
| 主要风险 | 解析错误、离散误差、随机误差、局部最优、参数误差或模型错配 |
| 可能后果 | 数值轻微变化、方案排序改变、约束失效或安全风险 |
| 验证方式 | 与风险直接对应的实验、证明或对照 |
| 判定阈值 | 来自题目精度、数值误差、统计功效或决策裕度 |
| 证据文件 | 实际结果、日志、证明或图表 |

没有对应风险的验证不强制执行；存在高风险却没有验证时不得交付。

## 二、条件触发

### 离散采样、网格或时间步

仅当模型确实使用表面点、粒子、网格、时间离散或数值积分时执行收敛扫描。档数、步长和容差由误差阶、计算预算和决策裕度决定，不固定为四档或 1%。报告完整序列、选定精度和继续加密是否可能改变结论。

### 随机模拟或随机算法

报告种子策略、重复次数依据、均值或分位数、区间、不稳定或失败次数。若结论是决策而不是均值，直接统计决策翻转率和后悔值。单个固定种子不能证明稳健。

### 启发式或非凸求解

优先使用小规模精确解、可计算上下界、网格、多起点和预算公平的重复实验。仅在算法机制可能影响结论时增加异构求解器；完全枚举、闭式解和有最优性证书的凸模型不触发。

### 参数不确定性和灵敏度

只扰动可能影响结论且有现实不确定性的参数。参数存在耦合证据时做联合扰动、场景或全局敏感性；没有耦合依据时不为凑表强制双参数扫描。报告决策边界、翻转率或风险，而不只报告输出变化百分比。

### 物理与几何简化

按 `../../innovation-special/references/物理几何简化.md` 使用 G1 等价证明、G2 内外界、G3 误差界或 G4 高保真对照。图形只能解释证明。

### 判据语义、边界延拓与优化器漏洞

按 `../../innovation-special/references/判据语义与边界审计.md` 核对主体、对象范围、量词和可执行接受测试。代表点/平均/松弛代理可以用于搜索，但最终 incumbent 必须用严格合同重新计分。

对源码中的 `clip`、`maximum`、`minimum`、饱和、落地停止、反射、吸收和越界延拓进行实现扫描，逐项回指建模报告中的边界来源。当最优候选贴边、饱和寿命/容量、依赖新代理或实质改变排序时，强制输出活跃约束、边界穿越、代理差值和局部扰动证据。题面未规定的边界在评价时窗内被达到时，结果标为 `UNCERTIFIED`，不得因代码能运行而通过。

### 数据驱动模型

按数据结构使用留出、滚动回测、分组外推、残差诊断、校准或分布漂移检查。训练集拟合优度不能替代外部验证。

### 核心反演、估计与多口径差异（本地 P4）

参数反演或估计算法驱动核心结论时，必须做任务特异的回收或辨识性验证；有多种口径时，再做差异处置。

1. **任务特异回收**：用与题目模型同构的正向生成器产生已知真值，注入与实测相符的噪声、缺失和干扰参数，再运行实际回收链。报告偏差、弥散、覆盖率、失败率和不可辨识区。自生成数据只能验证实现与“在假定模型成立时”的可恢复性，不能证明物理模型、材料参数或数据窗口正确。
2. **差异触发**：比较两个口径时先定义题目精度、决策裕度或统计阈值。同一数据上的两个估计通常相关，优先用配对 Bootstrap、联合蒙特卡洛或解析协方差估计差值不确定度
   `u_Δ² = u₁² + u₂² − 2cov(θ₁,θ₂)`。只有在独立性和近似正态性有证据时，才可令协方差为 0 并使用 `2√(SEM₁²+SEM₂²)` 作为默认警戒线；否则不得套用该式。差异超过阈值或会改变答案/排序/可行性时，强制进入第 3 步。
3. **逐层定位**：依次排查实现错误与数值误差、测量/抽样随机性、参数不确定性、模型形式与适用域。通过替换模块、固定公共输入、关闭某项机制、窗口交叉验证或外部锚点定位来源。不能由现有实验唯一分解时，报告“未辨识”，不要虚构每一部分的数值占比。
4. **不确定性账本**：对随机/测量、数值离散、参数输入和模型形式四类逐项记录“是否相关、证据、量化方式、区间或未量化原因、对最终结论的影响”。Bootstrap 只覆盖其重采样设计包含的随机性，不能自动代表系统误差或模型形式误差。
5. **表述边界**：差异由模型选择或窗口选择主导时写“模型形式差异”；只有任务特异实验支持某物理机制且方向、量级一致时，才可写成该物理效应。未闭环时给受限区间或并列结果，不输出唯一点估计。

`../scripts/synthetic_recovery.py --demo` 只是 Airy 薄膜示例，用于展示回收检验的报告结构。正式验证必须在 `PROJECT_ROOT` 编写并运行题目专用脚本；禁止修改只读 `SKILL_ROOT` 中的示例后冒充项目证据。

## 三、边界与反例

边界工况来自当前题目的参数域、时间窗、几何退化、容量、概率边界和决策阈值，不复制往届题目数值。优先测试最可能改变可行性、排序和安全结论的方向，并记录失败结果和回退策略。

## 四、证据要求

所有正文验证声明必须对应真实代码、命令和 `results/` 产物。禁止把“计划验证”“已有基础”或不存在的脚本写成已完成。验证结果发生变化时，相关创新状态和论文主张必须重新审计。
