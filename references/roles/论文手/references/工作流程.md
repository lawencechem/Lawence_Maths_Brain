# 论文手工作流程

## 一、锁定官方规则

生成前确认目标竞赛、届次、语言、用户指定的交付格式和官方规则来源。优先使用用户提供或从官方网站取得的当届官方 Word/LaTeX 模板、摘要页、编号页和格式说明。默认只生成 Word；用户指定 LaTeX/PDF 或双格式时按指定范围生成。当届官方提交要求仍决定实际可提交的版本。

## 二、检查输入

必须具备：

- 题目及附件
- `题目分析报告.md`
- `术语表格.md`
- 可运行代码
- 实际运行结果表格
- `results/创新证据清单.json`；允许 `items` 为空，所有采用项已通过审计
- 题目分析报告存在 `competitive` 子问题时，`results/竞争性搜索账本.json` 已通过挑战审计
- `results/图表论证清单.json` 及其中采用的图、表、公式和代码证据；几何图不得停留在 `PENDING_RENDER`
- 已核验的文献元数据

关键输入缺失时回退到对应角色补齐，不能推测数值、伪造图表或编造引用。

## 三、内部论证映射

写作前核对 `results/创新证据清单.json` 与 `results/竞争性搜索账本.json`（如有）的 SHA-256 与 `P2` 审计回执输入快照一致：一致 → 沿用 `P2` 回执，不重跑审计；不一致 → 返回编程手重跑对应审计并复验 `P2`。存在竞赛型子问题时按 `../../../竞争型问题协议.md` 读取挑战审计结果。读取创新清单、竞争性搜索账本（如有）和图表论证清单，在内存或临时工作区建立主张—证据映射：每个结论对应公式、表格、图、代码输出或文献。只有 `ADOPTED` 项可称为创新；`VERIFIED` 只说明证据成立，不自动获得创新地位。竞赛型还要把 baseline、内部标尺、incumbent 和停止证书映射到结果与局限章节。

同时记录两类篇幅约束：当届官方页数、摘要和文件限制是硬约束；`W1` 的逐章页数/内容预算是可调整质量目标。不得把往届页数或经验字数写成当前官方最低要求。

## 四、W1 证据大纲

W1 阶段先产出页数/内容预算表并纳入大纲：逐章列目标页数、主张和证据载体，合计不超过当届官方上限；摘要单独服从当届规则。写作中持续核对预算，结构冻结后用实际渲染确认。

在长篇正文和双格式排版前，为每个子问题列出拟写核心主张及其公式、结果表行列、图文件、代码输出或已核验 DOI，由独立质检 Subagent 检查：

- 每个必须回答的结论类型都有精确证据路径。
- 摘要拟用关键数值与实际结果一致。
- 摘要和正文的创新表述逐项来自 `ADOPTED`，并与代码、证明、结果、合理基线和失效边界一致。
- 竞赛型结论与搜索账本一致；只有 `PROVEN_OPTIMAL` 使用“最优”，其他停止理由使用“当前最好已知方案”并披露 gap、预算或未探索前沿。
- 公式、图表和引用都有章节落点。
- 每幅 `KEEP` 图都有图前引入、图后客观观察和对模型或决策的推论；连续两幅独立图之间存在正文过渡。
- 机理图靠近机理推导，流程图靠近算法说明，架构图靠近总体建模，验证图靠近指标定义；没有把图片统一堆到结果章节末尾。
- 不存在 `PENDING_RENDER`，`MERGE/APPENDIX/DROP` 均有可核对理由。
- Word 与 LaTeX 共用同一份正文和证据源。

存在核心证据缺口时返回建模手或编程手补齐；`W1` 未返回 `PASS` 不开始正文。证据大纲仅用于内部验收，不新增固定交付物。

## 五、构建论文

先锁定一份权威正文、数据、图表、公式和参考文献，再生成用户要求的格式；双格式不得分别改写导致结论或数值不一致。

### Word 分支

1. 从当届官方参考模板创建文档；模板正文示例必须清除，但保留样式、分节、页眉页脚和页面设置。
2. 使用 `../../../../tools/docx/scripts/paper_format.py` 添加标题、段落、公式、表和图片。
3. LaTeX 只作为公式输入，转换成 Word 原生 OMML；不支持的命令必须报错。
4. 表格使用可编辑 Word 表格；图使用编程手实际生成的文件。
5. 每幅图和每个表均设置连续编号与题注，并在正文中至少引用一次；按清单写入图前引入、图后观察和图后推论，文献编号、正文引用和 DOI 双向核对。

已有完整 LaTeX 主稿且需要同时交付两种格式时，可调用 `docx(action="convert_latex")` 或 `equations.py convert-latex` 生成 Word 初稿，以减少正文漂移；随后仍须按官方 DOCX 模板检查样式、分页、浮动体、交叉引用和参考文献。

### LaTeX 分支

1. 先运行 `latex_paper.py doctor` 检查官方模板需要的引擎、参考文献后端、PDF 审计工具和 Pandoc（需要 Word 时）。
2. 用 `latex_paper.py init` 把当届官方 LaTeX 模板整个目录复制到 `PROJECT_ROOT/完整论文-LaTeX/`；保留 `.cls`、`.sty`、`.bst`、字体和模板图片，并记录模板 URL、届次、哈希及嵌套主入口。没有官方模板时才使用内置构建基线。
3. 在复制件中填充正文、公式和已核验的 BibTeX 条目，不修改原始模板或 `SKILL_ROOT`。把 `PROJECT_ROOT` 权威代码和图表复制到 LaTeX 项目后，立即用 `latex_paper.py bind` 建立资源哈希绑定；每个子问题至少安排一个标签以 `fig:qN-`、`tab:qN-` 或 `eq:qN-` 开头的正式证据单元。
4. 按官方模板要求选择 XeLaTeX、LuaLaTeX 或 pdfLaTeX，优先由可实际执行的 `latexmk` 编译；不可执行且无外部文献时回退为两次所选引擎编译。不启用 shell escape，不自动安装宏包，不在失败后擅自换引擎。
5. 消除编译错误、未解析交叉引用和未解析文献；每个图表都有题注、真实内容与 `label`，并由图表环境外的正文 `ref`。同时检查权威资源—源码—PDF 哈希、PDF 总页数、正文页数、附录边界、空白页、页面尺寸、字体嵌入和图片 DPI。

## 六、验证

最终冻结时，按论文手 `SKILL.md` 的「完成门禁」运行内容审计，再对用户要求的每种格式执行对应工具 `SKILL.md` 的唯一权威验证清单。工作流程不复制命令，避免与工具清单漂移。构建与转换警告默认阻断发布；任何覆盖必须记录官方条款、用户要求或可复核理由。自动校验后仍需打开实际渲染结果抽检版面。

## 七、W2 论文终检

用户要求的全部格式冻结且各自确定性门禁全部返回 0 后，按 `../../../../references/Subagent调度.md` 派发独立质检 Subagent。质检者核对当届规则、主张—证据、数值与单位、图表编号和正文引用、文献及实际渲染效果；同时生成两种格式时再检查 Word/LaTeX 一致性。失败回执必须定位到页码、章节、命令或来源，并按根因返回对应角色；`W2` 未返回 `PASS` 不得交付。

## 八、交付

按用户指定格式交付：Word 为 `PROJECT_ROOT/完整论文.docx`（转换生成时附 `.conversion.json`）；LaTeX/PDF 为源码项目、实际编译 PDF 和 `.build.json`。临时 Markdown、内部映射、检查日志和中间文件不作为交付物。
