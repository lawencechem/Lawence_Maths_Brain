# 论文终审清单

论文交付前的最后一层确定性核对，把 2022B 事故暴露的 6 类错误（C1 数值断言未核验、C2 隐含协议未显式化+引证不精准、C3 先验阈值口径不诚实、C4 定性结论未量化、C5 表述与实现不一致、C6 编辑残留+格式缺陷）按「能否机械核验」拆开：**能脚本化的逐项自动化，绝不靠清单人工打勾；不能脚本化的给判定协议，不给笼统的"再检查一遍"。**

本清单是作者侧在 `W2` 之前完成的机械核对 + 判定核对，**不替代** `W1`（证据大纲）、`W2`（独立论文终检）、`自审框架.md` 的 `M0/M0-1/M0-2` 全流程门禁；也不重新验证建模正确性或证据大纲。范围明确：**只核验「正文声称 ↔ 项目证据（results/、代码、题面）」的一致性**。

## A 类 · 确定性脚本（C1/C5/C6，逐项自动化）

以下检查必须由脚本执行并 0 命中（或每条有明确解释与修正）后，才允许进入 `W2`。脚本按项目维护；2022B 事故项目的 `review_lint.py` 是可配置模板，含下列全部检查模式：

1. **数字 ↔ results 同源（C1）**：从正文叙述提取数字（排除表格、公式、`includegraphics` 参数），逐个在 `results/*.json|csv` 找同源（按量纲相对容差）。找不到同源 → 该数字是"凭记忆/未核验"写入。
2. **关键口径锚点（C1）**：论文关键声称值（初始最大偏差、最优间距、首轮集合等）与 results 实际值逐项比对，必须一致（容差内）。
3. **判据/方向类一致性（C1①）**：论文对具体配置给出"病态/适定/退化"等判定时，与对应结果文件（如方向扫描的条件数）比对——2022B 曾把 $\theta\approx180^\circ$（$\kappa\approx11$，适定）误判为病态。
4. **表述 ↔ 实现（C5）**：论文声称的算法选择/轮次/行为与实现代码或结果文件一致（2022B 曾声称首轮取 FY02、FY04，实现却是另一组合）。
5. **占位符与编辑残留（C6a）**：`TODO`、`待补`、`占位`、`待定`、`（待…`、`\textbf{…句}` 等。
6. **caption 双重编号（C6b）**：`\caption{表 N …}` / `\caption{图 N …}` 手写编号前缀——会与自动编号撞号（2022B 一个 figure 的 caption 以"表 1"开头）。

每类命中必须追溯到**行号与真值**（不是"发现 N 个问题"）；脚本的 `--demo` 模式应注入已知缺陷验证自身命中能力，避免"脚本零输出但根本没抓到"。

## B 类 · 判定核对（C2/C3/C4）

### B1 · 假设/引证逐字支撑三档（C2）

假设表里每个主张的依据必须标注支撑档位，且**引用的句子必须真的支撑所引的主张**。2022B A8 曾用题面"其余无人机根据接收到的方向信息调整到理想位置"支撑"发射机当轮不接收、接收机不发射"——引句并不支撑该主张，属引证句错配：

- **逐字支撑**：主张 ⊆ 题面字面，引用句给出题面原文片段（如"由编队中某几架无人机发射信号、其余无人机被动接收信号"）。
- **结构推导**：主张题面未明说，但从题面划分/定义**必然**推出，必须写清"从哪句、怎么推出"（如"发射/被动接收"互斥 → 发射机当轮不接收）。
- **建模选择**：题面没提，是模型自己的选择，必须显式标注（如机间不交换夹角观测），不得用不支撑它的题面句充当依据。

主体主张的引句错配或档位标注缺失 → C2 缺陷，修正引句或改标注。

### B2 · 反向锚点（C3 先验阈值口径不诚实）

对每个先验阈值/口径类声称，除正向"有依据"外，还要**反向**核对论文是否把题面/数据给定条件包装成了模型内在能力：

- 该阈值/先验是**数据/题面给定的外部条件**，还是模型推导或求解得出的结论？前者必须在正文显式声明"依据表 1 偏差尺度取定，非模型内在能力"（2022B 的 $D=15$~m 微偏差先验）。
- 论文是否声称了它其实不拥有的能力（如"排除远场对偶解"实则依赖外部先验）？
- 对应表述写"依赖数据先验/外部条件"，不得写成本模型性质。

### B3 · 定性结论必须有数字锚点（C4）

正文每个定性结论（"精度较高""方案稳健""显著改善"）必须能找到对应数字/结果锚点；找不到 → 补上数字，或删去/弱化该结论。

## 传导条款（写作时绑定，堵 C2/C3 的传导断点）

2022B 事故根因之一是**字段→正文传导断点**：建模/求解阶段已经定好的口径（$D=15$~m 先验、max_dev、首轮集合）在写作阶段没有被准确传递。因此：

- 每个关键数字在**写入正文的当时**就绑定 `results/` 中具体文件与字段，禁止"先写后查"。绑定可写在正文旁注或内部核对清单。
- `M0-2` 把关参数来源（建模侧"为什么选这个参数"）；本条款把关**参数值及其口径在正文中的呈现**与建模/求解侧一致——同一个 $D=15$~m，建模侧是"数据先验"，正文不得写成"模型能力"。
- 终审时抽查**反向追溯**：从正文数字出发，能否定位到 results 里的原始出处？找不到 → 传导断线，回到写作处补绑定后重跑 A 类脚本。

## 与既有门禁的分工

- 建模正确性、模型数量、验证完备性 → `M1`/`P1`/`P2`。
- 证据大纲、创新表述、竞赛型结论措辞 → `W1`。
- 当届规则、格式、渲染、Word/LaTeX 一致 → 论文手完成门禁 + `W2`。
- 本清单只核验「声称 ↔ 证据」一致性，不重复以上任何一层，也不重新验证求解正确性。
