# 教训与反模式（错题本）

记录跨项目重复出现的失败模式。每条含：现象 / 根因 / 强制规则 / 触发时机。

**加载方式**：只在被显式指向时才会被读入（PULL，不 PUSH）。各条教训的触发入口见对应角色 SKILL.md「何时加载」表与本仓库 `references/README.md`；A1 挂论文手修改入口，A3 挂编程手竞赛型求解入口。没有加载线的记录等于不存在。

## A1 修改/返工被拉成全流程重跑（拖沓主因）

- **现象**：用户要求"改 X"，执行者没分诊，先读遍全项目、列全流程重构计划、动手前零产出；用户明确不满"改得太慢磨磨唧唧"。
- **根因**：门禁文化奖励"完整"，歧义请求默认走全量；缺修改入口分诊。
- **强制规则（修改入口分诊协议）**：任何修改型请求，动手前 30 秒内输出成本单——按 论述/格式、数字/结果、模型/方法 三档分诊，逐项列最短路径与时间；**先做便宜的**（论述级立即执行、不等授权）；数字/模型级把成本报给用户让用户选，禁止静默拉全流程。评审类输入先输出"哪几条即改、哪几条要动代码重跑"的拆分表。
- **触发时机**：修改/返工论文、按评审意见改、按终审清单改。

## A2 没有项目级状态，每次修改从零读全项目

- **现象**：每次修改都重新读全项目，已核对的结论、已过的门禁、文件哈希不缓存，反复支付重读成本。
- **强制规则**：维护项目状态快照（关键数字、证据文件 SHA-256、门禁回执），修改只重跑受影响范围。
- **触发时机**：任何多轮项目。

## A3 启发式 incumbent 缺机制不同的求解器对照（评审必挑点）

- **现象**：25A Q5 用边际贪心，账本以 representation+objective 两条**同框架**挑战发 `DIMINISHING_RETURNS` 停表，无 MILP/遗传/差分进化/束搜索等机制不同的对照；评审一眼看穿"贪心不能证优，你对照了吗？"。且 Q2/Q3 声称"差分进化未找到更优"，但 DE 只在原型脚本、不在主流程——"跑过"与"主流程可复现"是两回事，后者才是 C5 意义上的证据。
- **根因**：挑战顺序⑤"求解结构"是建议语不是门禁；`DIMINISHING_RETURNS` 只要求"≥2 条结构实质不同"，被 representation+objective 在同一求解框架内凑满。
- **强制规则**：当 incumbent 由已知启发式（贪心、局部搜索、单纯形、采样+局部精化）产生且非 `PROVEN_OPTIMAL` 时，发出停止证书前**必须**做至少一次机制不同的求解结构对照（MILP / 遗传 / 差分进化 / 束搜索 / 精确枚举等），并把对照数值写入账本与论文；"更换同类求解器"或"增加随机种子"不满足。"声称跑过 X 求解器"必须有主流程可复现代码。
- **触发时机**：竞赛型求解准备发停止证书；论文写作报告"未找到显著更优"时。

## A4 角色交接查"存在"不查"完成"，半成品当已完成传给下家

- **现象**：25A 论文手开局就补编程手的活——Q5 账本 `CHALLENGE_OPEN` 未闭合（结果 10:52 完成、账本 10:39 就停了）、`result_q5_timeline.png` 缺失、`result1/2/3.xlsx` 缺失、账本/创新清单字段与审计脚本 schema 不符被重写。四项全是编程手固定交付物，没有一项属于论文手。
- **根因**：交接门禁查"文件存在"不查"状态完成"（账本文件在但 state 是半成品）；编程手 P2 因会话中断未跑到、没有回执可比对；论文手默认"顺手补"而不是"回退编程手"，把失败流程接了过来，后续 W1/W2 连环暴露更多遗留（result1 有效时长全 0 等）。
- **强制规则**：① 编程手 P2 前过「交付物完成自检」——账本全 `CHALLENGE_CLOSED`、图表无 `PENDING_RENDER` 且文件齐全、结果表齐全、复现命令覆盖全部交付物生成链；② 论文手开始门禁做「完成态门禁」——任何未闭合项**回退编程手，禁止代补**（仅用户显式授权可代补并记录授权理由）；③ 阶段被中断时写 `未完成项清单.md`，接手角色先读它判断回退还是授权代补。
- **触发时机**：角色交接、会话中断后恢复、任何"文件在但流程未闭环"的项目。

## A5 工具/权限被拦时闷头自修，不立即升级给用户

- **现象**：25A 求解阶段权限分类器持续拦截 Bash，执行者耗约 40 条消息自我修复——配 settings、被拒、还原、请用户 `!` 运行、建议重启，最后才把最短路径交给用户；中间还要用户亲手贴命令跑 q5.py。
- **根因**：skill 无"执行工具被拦 → 立即升级"分诊，门禁文化奖励"自己解决"，把环境问题当任务问题硬扛。
- **强制规则**：执行类命令被权限系统/分类器拦截时，最多试一次配置放行；仍被拦即**停止自修**，立即给用户最短路径（具体命令清单请用户运行，或提示切换权限模式），说明备选与"已完成工作已存盘、重启不丢"。禁止多轮自我修复权限。
- **触发时机**：任何 Bash/工具调用被拦、权限模式异常、会话配置漂移。
