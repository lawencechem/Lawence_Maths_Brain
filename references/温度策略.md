# 发散—收敛温度策略（提示词级"调数"）

## 原则

- 本 Skill 通过提示词控制每阶段输出**多样性 / 确定性**，等效于调节 temperature，但**不修改、不声称修改任何会话 temperature 配置**（如外部 cc-switch/router 配置的 0.2）。
- 本文件只负责"发散—收敛的**节奏与终点**"，**不负责发散内容**；发散内容（选什么模型、怎么创新、怎么算真创新）由 `roles/innovation-special/SKILL.md` 负责，二者互补不重叠。
- 全程不碰配置，"最后返回原始值"天然成立：原始值从头到尾不变，不存在改坏忘还原的问题。
- **禁止**在任何进度、日志或完成声明中谎称"已将温度调到 X"；"调数"指调节发散节奏，不是改 API 参数。

## 三档发散节奏（只规定节奏，不规定内容）

| 档位 | 适用 | 节奏要求 |
|---|---|---|
| 高发散（≈高温） | 建模手：题眼、选模型、定假设、创新点 | 在创新专项基础上先扩宽方案空间，再收敛 |
| 收敛（≈低温） | 编程手：求解、数值计算、写代码 | 按已定方案执行，不即兴引入新思想，可复现 |
| 中发散 | 论文手：表达组织、管理/工程启示 | 已定模型与真实数据范围内多样化表达 |

## 高发散档（节奏）

1. 发散的内容（创新等级、防伪判定、三段论证）按 `roles/innovation-special/SKILL.md` 执行，不另起炉灶。
2. **扩宽动作是本档的硬性节奏要求**：选择最终模型前，强制先产出候选池——≥3 条**结构实质不同**的模型路线（控制机理/状态变量/求解目标不同才算，见建模约束 2），至少含一条非常规路线，逐条标注适用边界与"若采用会改变哪个环节"。此为决策过程要求，不评价创新等级；等级与防伪由创新专项判定。
3. **发散后必须收敛**：按当届评阅要点与题目约束排序选优，写出选择理由，不把候选清单原样丢给下游。

## 收敛档（求解阶段强制要求）

1. 严格沿用建模手已确定的变量、公式、假设，禁止中途引入新模型思想。
2. 以复现为先：固定随机种子、输入文件哈希、关键参数表，见 `编程手/references/工作流程.md`。
3. 遇到可改进点时记录为"优化候选"，不在求解主链上即兴修改。

## 中发散档（论文阶段）

- 正文严格按已定结构、真实数据与结果写作；表达层面允许多样。
- 管理/工程启示段可从多个受益方视角展开（见 `roles/innovation-special/元能力.md` 第 4 条）。
- **禁止**在论文阶段发明新模型、新结论或未运行的数据。

## 回到默认策略（结束还原）

- 每个高发散任务结束、回到主流程前，先明确"已回到收敛档"。
- 全流程结束的完成门禁增加一项：确认未改动任何 temperature 配置（原始值未变）。
- 单阶段任务同理：发散子任务用后即收，不把发散状态带进后续任务。
