# 竞争型问题协议

## 目标

把“结果正确”和“方案有竞争力”拆成两个正交门禁。真实性总闸始终优先；竞赛型问题在得到首个可行解后继续进行有预算、有标尺、可复核的挑战，禁止把“达标”写成“完成”。

## 一、逐题分类

在阶段 0 为每个子问题设置 `completion_mode`：

| 模式 | 识别信号 | 完成条件 |
|---|---|---|
| `conformance` | 计算、拟合、预测、证明、填表或满足给定精度，答案合同相对闭合 | 必答项、正确性和复现门禁通过 |
| `competitive` | 最优、最少、尽可能、最佳设计、多目标权衡，或存在大量质量不同的可行方案 | 真实性门禁通过且竞争性停止证书成立 |

不要只按动词判断。若一个优化问题可由闭式解、凸性、完全枚举或上下界闭合证明最优，仍标记为 `competitive`，但可用最优性证书结束。含硬约束和软目标的问题也标记为 `competitive`：硬约束负责可行，软目标负责竞争。

在 `题目分析报告.md` 的子问题拆解中记录：

- `completion_mode` 与判断依据。
- 硬约束、软目标、目标方向、优先关系或 Pareto 口径。
- 可行基线、内部标尺、预期瓶颈和验证方式。
- 挑战预算及分配依据。
- `problem_class`：用题目实质描述，如 `dynamic_control`、`layout_structure`、`resource_allocation`、`model_selection`；不得因分类名不在示例中而留空。
- `decision_space_audit`：按 `roles/innovation-special/references/决策空间完备性.md` 记录四类自由度、新增/重复对象、聚合假设，以及实际命中的 `structure_triggers`。不要让 Agent 自评 `high/low`；多对象、聚合压缩或分配/时序/分层等信号直接触发 `structure_probe`。
- `model_contract_audit`：按 `roles/innovation-special/references/判据语义与边界审计.md` 记录判据主体、对象范围、量词、严格接受测试、状态域/边界后行为、代理关系及 incumbent 严格合同认证。优化得分不能自证判据正确。

`M1` 必须核对分类。出现“尽量、尽可能、最优、最少、最佳”而标为 `conformance` 时，必须给出唯一答案或无需竞争搜索的证明。

## 二、两闸一棘轮

1. **真实性闸**：候选必须满足判据语义、物理、量纲、边界条件、约束、数据口径和复现要求。数值更好不能覆盖真实性失败。搜索可使用代理，但 incumbent 必须由严格合同重新计分。
2. **竞争性闸**：`competitive` 子问题不能在首个可行解处关闭；必须建立内部标尺、执行结构性挑战并形成停止证书。
3. **incumbent 棘轮**：冻结当前最好可行方案。所有挑战在隔离分支或独立函数中运行；只有真实性通过且按既定目标口径更优的挑战者才能替换 incumbent。替换后重跑受影响的模型、结果和门禁。

## 三、内部标尺

官方最优值缺席时，至少建立一种与赛后答案无关的标尺：

- 解析、几何、容量或松弛下界。
- 小规模精确解、完全枚举或 MILP/DP 对照。
- 保持硬约束的理想化 Oracle。
- Pareto 前沿、支配关系或 epsilon-constraint 前沿。
- 相同输入与预算下的合理基线。
- 逐层包含的决策空间，如固定结构 → 分区结构 → 自适应结构。

只报告“比初始方案好”不等于证优。能计算界时报告 gap；不能计算界时明确写成“当前最好已知方案”，并保留未探索前沿。

## 四、挑战顺序

先诊断瓶颈，再选择挑战，不用算法数量制造探索感：

1. **目标口径**：检查权重、词典序、epsilon 约束或 Pareto 口径是否忠实反映题意。
2. **判据合同（先于挑战）**：按 `roles/innovation-special/references/判据语义与边界审计.md` 锁定对象范围、量词、代理关系和边界条件。代码中任何无来源的 `clip/max/min`、饱和或边界后行为，以及代表点/平均代替延展对象，都使候选进入 `UNCERTIFIED`。最终 incumbent 必须通过严格合同和边界穿越复核。
3. **决策表示（信号触发）**：先建立领域关系→数学映射和聚合假设审计。存在新增/重复对象、聚合压缩，或分配、相对时序、分层、混合离散—连续、高维黑盒等 `structure_triggers` 时，在昂贵搜索前完成一个 `structure_probe`。探针只保留机制观察、候选及证据；每个候选直接处置为挑战、题面固定、证据性拒绝或未探索。挑战用 `candidate_ref` 回指候选，并用 `representation_delta` 明列基线决策、挑战决策、新增/解除的关系及同口径证据；同空间换求解器、种子或参数不算表示挑战。命中结构信号且未证最优时，停止前至少完成一次表示/分解挑战。
4. **结构分解**：尝试分区、分段、分层、列生成、动态状态或跨问共享信息。
5. **模型与信息**：检查被忽略的机制、反馈、不确定性或可利用数据。
6. **求解结构**：最后再针对已证实的局部最优、规模或在线瓶颈改进求解器。

参数微调、增加随机种子或更换同类求解器可以用于验证，但不能单独满足结构性挑战要求。审计器只能核对证据结构，不能证明文字陈述真实；`M1/P2` 仍须对照题目、代码和证据文件确认 `representation_delta` 确实改变了可行决策空间或分解接口。

账本中的 `decision_space_audit` 和 `model_contract_audit` 是建模报告的机器可检副本。`freedom_families` 必须恰含四类；新增/重复对象或聚合压缩会直接触发 `structure_probe`，其他结构信号写入 `structure_triggers`。探针候选的处置只允许 `CHALLENGED/FIXED_BY_PROBLEM/EVIDENCE_REJECTED/UNTESTED`，并链接真实挑战、证据或停止前沿。`model_contract_audit` 有代理时，除最终严格认证外还必须记录代理—严格判据的排序/可行性对照；发生分歧必须让严格判据进入搜索或拒绝代理。

对 `competitive_relevance: high` 且原型成本在预算内的候选，必须完成最小原型。无证据时保留为 `HYPOTHESIS` 并登记到未探索前沿，不得仅凭主观理由改为 `DROPPED`。

## 五、资源策略

先让所有子问题形成正确可交的基线，再把剩余资源按下式的相对关系分配给竞赛型问题：

`优先级 ∝ 区分度 × 潜在改进空间 × 跨问价值 ÷ 实现与验证成本`

预算可以使用墙钟时间、函数评估次数、求解器节点数、仿真次数或人工原型轮次。预算必须在挑战前登记；不要事后把已经花掉的资源包装成计划。

## 七、停止证书

只允许以下停止理由：

- `PROVEN_OPTIMAL`：最优性证明或上下界闭合。
- `GAP_TARGET`：可复核 gap 不超过预先声明阈值。
- `BUDGET_EXHAUSTED`：预先分配预算已耗尽，并列出未探索前沿。
- `DIMINISHING_RETURNS`：至少两条结构实质不同的挑战路线均低于预设边际收益阈值。
- `BLOCKED_BY_CONSTRAINT`：数据、物理或工程硬约束有证据地阻断继续扩张。

“已经可行”“验证全过”“结果看起来不错”“没有官方答案”均不是合法停止理由。不要写“全局最优”，除非停止证书为 `PROVEN_OPTIMAL`；其余情况写“当前最好已知方案”及剩余 gap 或未知项。

`BUDGET_EXHAUSTED` 还必须给出 `gap_assessment`。gap 不可计算时说明原因；可计算且超过 50% 时，这个阈值只触发诊断而不宣称上界紧：若界/Oracle 有信息量，必须链接一次由该 gap 触发的表示/分解挑战；若界过松，必须用证据修正或撤销该标尺。两者都没做时不得关闭搜索。这样既拦截“大 gap 仍直接收工”，也避免被无意义松界拖入无限计算。

## 八、盲做边界

实时参赛时禁止读取官方答案、赛后解析和同题论文，也禁止把网传数值当作目标。内部标尺必须来自题面、赛前文献、数学界、基线或当前实验。历史题回归测试时，把赛后结果仅交给外部评测器；执行该 Skill 的 Agent 不得看到目标数值和预期方法。
