# 视觉论证与配图策略

本参考负责把论文配图从“按图型或数量生产”改为“补齐论证缺口”。官方规则、数据真实性和模型定义始终优先于视觉表达；数据图的具体绘制规范由 `../tools/figure/SKILL.md` 负责，机理、几何、流程、架构和拓扑图由 `../tools/diagram/SKILL.md` 负责。

## 一、视觉论证总契约

所有正式图以“补齐论证缺口”为生成单位，而不是以图型、题号或数量为生成单位。拟图前必须先登记读者疑问、核心主张、证据来源、视觉角色和章节落点；若表格、公式或文字能更直接完成论证，则不画图。

编程手建立候选证据池，论文手在 `W1` 阶段决定 `KEEP`、`MERGE`、`APPENDIX` 或 `DROP`。拟入正文的图必须形成“图前提出问题或判断依据、图中提供证据、图后说明观察结果及其对模型结论的含义”的闭环。

## 二、载体选择门禁

按下列顺序选择证据载体：

1. 先写出读者尚不能回答的问题和拟支持的主张。
2. 判断证据来自模型定义、真实数据、代码过程还是计算结果。
3. 在文字、公式、表格、数据图和非数据图之间选择最直接的载体。
4. 只有图能显著降低理解成本或揭示不可由文字直接读取的关系时才生成图。
5. 遮住该图仍不影响论证时，删除或合并该图。

| 证据任务 | 首选载体 | 路由 |
|---|---|---|
| 精确数值、参数清单、小规模方案 | 表格 | 论文手 |
| 定义、恒等关系、约束与推导 | 公式 + 文字 | 建模手、论文手 |
| 趋势、分布、误差、对比、收敛、敏感性 | 数据图 | `tools/figure/SKILL.md` |
| 物理机理、空间几何、传播或遮挡关系 | 机理/几何图 | `tools/diagram/SKILL.md` |
| 分支、循环、回退和阶段依赖 | 流程图（逻辑复杂优先 Mermaid） | `tools/diagram/SKILL.md` |
| 三个以上模块之间的输入、输出和耦合 | 架构图 | `tools/diagram/SKILL.md` |
| 节点、边、路径和连通性本身是决策对象 | 拓扑图 | `tools/diagram/SKILL.md` |

## 三、非数据图触发条件

满足任一条件时，将非数据图列为候选：

- 读者难以仅凭公式重建连续几何、坐标系、可见域、受力、传播或时空交叠关系。
- 算法包含至少四个有实质含义的阶段，且存在判断、循环、回退或并行分支。
- 模型由至少三个相互作用的模块组成，模块间传递的变量或控制关系影响后续推导。
- 路径、网络、装配、层级或依赖关系本身决定可行性或目标值。
- 后文多次复用同一组视觉对象，先定义统一视觉词汇可减少重复解释。

出现下列情况时禁止生成非数据图：

- 只是“输入数据 -> 建立模型 -> 求解 -> 输出结果”的通用流程。
- 只是把章节标题放入方框，没有分支、反馈、空间关系或模块耦合。
- 只把题目给出的常数、表格或已知条件改画成图。
- 图中对象或箭头无法对应到模型变量、公式、代码模块或真实数据。
- 无法写出图后新增的观察和推论。
- 与已有图表达同一信息，只是更换图型、视角或配色。

## 四、竞赛题型优先级

- 物理机理与空间问题优先考虑坐标系、关键几何关系、可见/遮挡边界、轨迹和时空交叠，不优先重复绘制输入参数。
- 离散优化问题优先考虑拓扑、装配层级、决策耦合、约束传播和算法分支，不为已知的小规模常数单独画图。
- 信号、光学和频谱问题优先考虑传播路径、处理链、残差、稳定性和判据诊断，不连续堆叠近似重合的频谱或曲线。
- 预测与评价问题优先考虑误差结构、区间、对照和敏感性；无法增加判断信息的“模型框架图”不进入正文。

## 五、三角色交接

### 建模手

在 `题目分析报告.md` 的每个子问题中记录：

```text
视觉论证需求：
- 读者疑问：
- 核心主张：
- 证据来源：模型定义 / 数据 / 代码过程 / 计算结果
- 建议载体：文字 / 公式 / 表格 / 数据图 / 非数据图
- 非数据图类型：机理 / 几何 / 流程 / 架构 / 拓扑（不适用则省略）
- 必须出现的对象与关系：
- 建议章节落点：
```

建模手只定义视觉需求和数学语义，不生成最终图，不新增固定交付物。

### 编程手

编程手依据真实模型与运行结果生成候选证据，并维护 `PROJECT_ROOT/results/图表论证清单.json`。原始数据、过程和结果可继续作为来源标签，但不构成逐题配额。

推荐结构：

```json
{
  "version": 1,
  "questions": ["q1", "q2"],
  "items": [
    {
      "claim_id": "Q2-C3",
      "question_id": "q2",
      "reader_gap": "读者无法从公式直接判断有效遮蔽区为何形成",
      "claim": "有效遮蔽由视线与烟幕区域的时空交叠决定",
      "evidence_source": "results/q2_geometry.csv",
      "carrier": "figure",
      "visual_role": "mechanism",
      "file_stem": "geometry_q2_occlusion",
      "placement": "4.2.2 遮蔽判据推导之后",
      "lead_in": "为说明遮蔽判据的几何含义，图中给出视线与烟幕区域的位置关系。",
      "post_observation": "有效区域只出现在两者同时交叠的时间窗内。",
      "post_implication": "后续优化应搜索交叠时间窗，而不是仅最大化烟幕持续时间。",
      "decision": "KEEP"
    }
  ]
}
```

允许的 `carrier` 为 `figure`、`table`、`equation`、`text`；允许的 `visual_role` 为 `mechanism`、`geometry`、`flow`、`architecture`、`topology`、`result`、`validation`、`robustness`。暂不采用的候选使用 `MERGE`、`APPENDIX` 或 `DROP`，并填写 `merge_target` 或 `drop_reason`；等待用户用 GeoGebra 渲染的几何图、以及 Mermaid 无法自动渲染的复杂流程图使用 `PENDING_RENDER`，并记录指令文件/`.mmd` 源码与生成说明路径。`PENDING_RENDER` 可以作为阶段性交付，但不能通过最终 `P2/W2` 门禁。

### 论文手

论文手在 `W1` 中完成最终取舍和章节落点。每幅 `KEEP` 图均应满足：

1. 图前先提出需要该图回答的问题或判断依据。
2. 图片位于第一次完整正文引用之后或紧随其后，不能提前出现。
3. 图后先写客观观察，再写对模型、算法或后续决策的含义。
4. 机理图靠近机理推导，流程图靠近算法说明，架构图靠近总体建模，验证图靠近验证指标定义。
5. 不连续放置两幅缺少过渡论述的独立图片，不把全部图集中到结果章节末尾。

## 六、数量与覆盖

- 每个子问题至少有一个可追溯的正式证据单元，证据单元可以是图、表、关键公式组或经核验文献。
- 图数和图型多样性是结果，不是生成目标；无论证价值的图不得用于满足数量或题号覆盖。
- 候选图可以多生成用于比较，但每张都必须进入图表论证清单并明确最终决策。
- 完整度检查只提示证据缺口，不以固定图数替代主张与证据检查。

## 七、文件与引用

- 数据图沿用 `raw_qN_*`、`process_qN_*`、`result_qN_*` 作为可选来源标签。
- 非数据图使用 `mechanism_qN_*`、`geometry_qN_*`、`flow_qN_*`、`architecture_qN_*` 或 `topology_qN_*`。
- Matplotlib 图和 GeoGebra 2D 图至少保留同源 SVG 和 300 DPI PNG；GeoGebra 3D 视图以 `.ggb` 或逐行指令作为可编辑源，并导出宽度至少 2000 px 的高分辨率 PNG。复杂判定/算法流程图的 Mermaid 源码 `.mmd` 作为可编辑源，同源导出 SVG 与至少 300 DPI PNG。LaTeX 安全编译链需要时再导出同源 PDF/PNG。
- GeoGebra 无法自动运行或导出时，在 `figures/` 中写入 `<stem>.geogebra.txt` 和 `<stem>_生成说明.md`；Mermaid 无法自动渲染时写入 `<stem>.mmd` 和 `<stem>_生成说明.md`；两者均不得用想象生成的替代位图冒充完成。
- 项目已有 `[[fig:...]]` 占位协议时保持其既有语法，不自行发明另一套占位格式；正式交付仍须检查题注、编号、正文引用和实际渲染位置。
